# Development Progress — 5 August 2026

This document records the Hospital Management System work completed and validated during today's development session.

## 1. Database-driven roles and permissions

- Added application-owned `Role`, `Permission`, and `RolePermission` models.
- Kept `CustomUser` on `AbstractBaseUser` without Django's `PermissionsMixin`.
- Replaced the old text-choice user role with a foreign key to `Role`.
- Added role and permission fixtures.
- Completed the idempotent `seed_permissions` management command.
- Added and seeded the `MANAGER` role.
- Exposed each authenticated user's active permission codes in profile and login responses.
- Updated the frontend to derive navigation and action visibility from database permissions.
- Ensured active REST endpoints use explicit `APIView` classes.
- Replaced Simple JWT's generic refresh view with an explicit `TokenRefreshAPIView`.
- Added an architecture test that fails if a future `/api/v1/` route does not inherit from `APIView`.
- Reduced `@extend_schema` annotations to frontend-useful tags, summaries, request/response contracts, query parameters, status codes, and content types.
- Corrected the misplaced staff-invitation schema and added missing password reset, medicine detail, token refresh, and health-check contracts.

## 2. Staff invitation and onboarding

- Added the staff invitation model, serializer, service, email helper, create endpoint, and acceptance endpoint.
- Required both `can_create_users` and `can_assign_roles` to send staff invitations.
- Created inactive staff users with no usable password until invitation acceptance.
- Added signed, expiring invitation tokens.
- Implemented invitation acceptance with password setup, activation, and verification.
- Kept the invited role as the source of the new staff member's permissions.

## 3. Patient and doctor profiles

- Added `first_name` and `last_name` to `CustomUser` and removed the unused username field.
- Confirmed public registration automatically creates a `PatientProfile`.
- Added patient profile self-service and staff patient-management APIs.
- Added doctor profile create, retrieve, and update APIs.
- Allowed doctors to complete their own specialization, licence, experience, biography, fee, and availability information.
- Added profile fields to frontend forms and confirmed values persist in both the user and doctor tables.

## 4. Doctor schedules and appointment integrity

- Added doctor self-service schedule APIs using the authenticated user's `doctor_profile`.
- Preserved manager-level schedule management for authorized roles.
- Generated appointment slots from schedule start time, end time, and session duration.
- Rejected times that do not align with a valid generated slot.
- Prevented double booking of pending or confirmed appointments.
- Allowed cancelled slots to be booked again.
- Added appointment filtering, ordering, search, confirmation, cancellation, and completion behavior.

## 5. Pharmacy and stock workflows

- Completed medicine list, create, detail, update, activation, deactivation, filtering, and ordering APIs.
- Completed prescription create, list, patient list, cancel, and dispense APIs.
- Restricted prescription ownership and management by permission and doctor ownership.
- Made dispensing atomic and idempotent.
- Deducted stock exactly once when dispensing.
- Connected cancellation, dispensing, restocking, and low-stock notification triggers.

## 6. Notifications and background work

- Added the notifications application and delivery records.
- Configured Celery, Celery Beat, and Redis.
- Added appointment cancellation emails.
- Added prescription dispensing and medicine restocking/low-stock notifications.
- Added scheduled appointment-reminder discovery.
- Added environment switches for enabling notifications and configuring reminder windows.

## 7. Billing and payments

- Added invoices and immutable invoice line items.
- Calculated invoice totals on the server using consultation fees and dispensed medicines.
- Added PDF invoice downloads.
- Added `InvoicePayment` with amount, method, reference, notes, recorder, and timestamp.
- Supported cash, card, mobile money, insurance, and bank-transfer records.
- Added partial and full payment support.
- Derived invoice status as `UNPAID`, `PARTIAL`, or `PAID`.
- Added transaction locking, overpayment prevention, duplicate-reference prevention, and fully-paid protection.
- Added payment permissions and assigned them to the receptionist and administrator roles.
- Added the frontend billing page for invoice creation, payment recording, balances, history, and PDF downloads.
